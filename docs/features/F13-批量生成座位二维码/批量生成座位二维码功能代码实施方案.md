## 实施计划

1. 后端请求与服务：新增 `Requests.SeatCodeBatch(reason)`；在 `SeatCodeService` 增加 `batchGenerate`，复用现有管理员校验、理由校验、脱敏、码生成、`booking_mutex` 锁与 `view` 元数据；查询缺码座位后逐座插入并写审计，返回 `total_seats/generated/skipped`。
2. 后端接口：新增 `SeatCodeBatchController`，`POST /api/admin/seat-codes/batch`，`@Valid` 接收理由，统一 `Api.ok` 信封。
3. 后端测试：新增 `BatchSeatCodeIntegrationTest`，使用真实 `studyroom_java_test`，覆盖缺码补齐、已有码与停用码跳过、PNG 真实解码、幂等、权限、参数、事务回滚和停用座位。
4. 前端：`api/admin.js` 增加 `batchGenerateSeatCodes`；`ResourceManagement.vue` 标题行新增入口、理由弹窗、成功/失败反馈；不改变单座位座位码弹窗。
5. 前端测试：在 `resources.test.js` 扩展组件脚本测试与 API 适配器测试，覆盖成功、空理由、403 与请求体。
6. 文档：需求规格新增 8.37 并把版本升到 v0.29；`docs/README.md`、`README.md` 登记 F13；按实际结果回写本文件验证记录与剩余事项。
7. 验证：后端相关集成测试与打包；前端 Node 测试与 production build；`python scripts/check_repository.py`；人工页面走查不代替自动测试，真实 288 座位部署由部署者执行。

## 实际改动与方案差异

与架构方案一致，无实质行为差异。

- `backend/src/main/java/cn/studyroom/Requests.java`：新增 `SeatCodeBatch` 请求记录，`reason` 非空且不超过 1000 字。
- `backend/src/main/java/cn/studyroom/SeatCodeService.java`：新增 `batchGenerate`。先锁 `booking_mutex`，校验管理员与理由，按 `seats.id` 顺序查询 `seat_codes` 无记录的座位；每个座位插入 `version=1/enabled=true` 的新随机码并写 `seat_code.batch_generate` 审计（前后值为安全元数据、理由脱敏）；返回 `total_seats/generated/skipped`。已有码座位不进入写入集合，不做轮换、启停或版本更新。
- `backend/src/main/java/cn/studyroom/SeatCodeBatchController.java`：新增 `POST /api/admin/seat-codes/batch`，只接受管理员；`/api/admin/**` 拦截与 `requireAdmin` 双重校验。
- `backend/src/test/java/cn/studyroom/BatchSeatCodeIntegrationTest.java`：5 条真实集成测试，见验证记录。
- `frontend/src/api/admin.js`：新增 `batchGenerateSeatCodes(data)`，请求 `/admin/seat-codes/batch`。
- `frontend/src/components/admin/ResourceManagement.vue`：标题行新增“批量生成缺失座位码”；弹窗说明只补缺码座位、要求操作理由；成功提示生成/跳过数量并保留结果通知，失败保留理由与弹窗；请求期间禁用重复提交。
- `frontend/tests/resources.test.js`：新增 API 适配器、成功数量提示、空理由与 403 保留弹窗三类测试。
