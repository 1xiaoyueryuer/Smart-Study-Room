## 目标、范围与验收

部署者在自己的主机数据库中已有 288 个座位、尚未生成任何座位码。逐座点击“首次生成”不可接受；本功能让管理员用一次操作，为**所有缺少座位码的座位**各生成一个当前码，**已有码的座位直接跳过**，不轮换、不启停、不改版本。开发者只需在本地少量座位上验证同一行为，部署者用管理员账号在目标库执行一次即可补齐，不需要交换数据库。

本功能是既有 S09 座位码“管理员初生成”的批量管理入口，不是新码制、不是签到规则变化，也不把二维码图片存入数据库。数据库仍只保存随机座位码，PNG 由既有 `QrImages`/`SeatCodeService.png` 按需生成。

| 需求编号 | 前提与操作 | 预期行为 / 拒绝条件 | 验证方式 |
|---|---|---|---|
| AC-34，FR-03/S09 | 库中 3 个座位，其中 1 个已有座位码；管理员执行批量生成 | 返回 `total_seats=3`、`generated=2`、`skipped=1`；2 个新码为 `studyroom-seat:v1:` 加 43 位 base64url、version=1、enabled=true；已有码的码值、版本、启停和时间不变；新码 PNG 可被真实解码 | 真实 `studyroom_java_test` 集成测试 + 真实 PNG 回读 |
| AC-35，FR-03/S09 | 同一库再次执行；学生/教职工执行；管理员缺少理由或理由超长；审计写入故障 | 再次执行 `generated=0`、`skipped=3`，不新增码或审计；未登录 401、非管理员 403；缺理由/空理由 400 且无写入；审计故障 500，整批座位码回滚为空 | 真实 HTTP 集成测试、事务回滚测试 |
| AC-35 边界 | 已有码已停用，或座位处于维护/停用、空间停用 | 批量生成跳过该座位并保持停用与版本不变；缺码的停用座位仍可生成码，但不会因此可预约或可签到 | 服务/HTTP 测试 |

成功标准：管理员一次操作后，“缺码座位”数量变为 0；已有码座位不被改写；重复执行幂等；失败不留下半批数据；普通用户无法调用或读取码值。

## 当前实现与模块职责

- `SeatCodeService` 已是每座当前码的唯一写源：单座位 `generate` 要求 version=0、理由、`booking_mutex` 锁与同事务审计；`rotate`、`setEnabled`、`png`、签到校验均已有。缺码判断来自 `seat_codes` 是否已有行。
- `SeatCodeController` 只提供 `/api/admin/seats/{id}/code` 系列单座位接口；`ResourceManagement.vue` 的座位行有“座位码”弹窗与“首次生成”按钮，但没有跨座位批量入口。
- 管理页已有理由校验 `operationReason`、统一错误提示、`SDialog/SButton/SInput` 与成功 `message` 反馈，可直接复用。
- 数据库 V8 `seat_codes` 以 `seat_id` 主键、`code_value` 唯一、`enabled`、`version`、时间字段保存当前码，无需新表或迁移。
- 既有 S09 测试覆盖单座位生成、轮换、启停、PNG、签到与审计回滚；本功能新增批量路径的集成测试，不重写这些规则。

## 数据、接口与流程

### 接口

`POST /api/admin/seat-codes/batch`

- 认证：`Bearer` 管理员令牌；`/api/admin/**` 与 `SeatCodeService.requireAdmin` 双重校验。
- 请求体：`{"reason":"部署前批量补齐缺失座位码"}`；`reason` 非空、去首尾空白后 1—1000 字。
- 成功响应（统一信封 `data`）：
  - `total_seats`：执行时全部现存座位数；
  - `generated`：本次实际新增座位码数；
  - `skipped`：已有座位码（含已停用码）而跳过的座位数。
- 不返回 `code_value`、码图片或他人信息。PNG 仍由单座位 `/api/admin/seats/{id}/code/png` 按需读取。
- 错误：未登录 401；非管理员 403；缺理由/超长 400；数据库/审计失败 500 并整批回滚；无座位时返回 `total_seats=0, generated=0, skipped=0`。

### 服务流程

1. 先取 `booking_mutex` 行锁，与单座位生成、轮换、启停和签到保持同一串行化边界。
2. 校验管理员与理由。
3. 查询 `seats LEFT JOIN seat_codes` 中无码的座位，按 `seats.id` 稳定排序。
4. 对每个缺码座位生成新随机码（与单座位首次生成同格式），插入 version=1、enabled=true；为该座位写一条 `seat_code.batch_generate` 审计，前后值为既有安全元数据视图，理由中的码值脱敏。
5. 统计全部座位数、生成数、跳过数并返回。
6. 任一座位插入或审计失败抛出异常，事务整体回滚；重复执行时无缺码座位，不写码也不写审计。

### 前端流程

管理端“自习室管理”标题行新增“批量生成缺失座位码”按钮。弹窗说明“只补齐缺码座位，已有码座位保持不变”，要求填写操作理由；提交成功后关闭弹窗，提示“已生成 X 个、跳过 Y 个”，并在页面保留结果通知。失败时保留理由和弹窗，显示统一错误。页面在请求中禁用重复提交。
