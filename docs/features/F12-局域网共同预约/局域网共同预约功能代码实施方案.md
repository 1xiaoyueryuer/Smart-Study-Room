## 实际改动与方案差异

### 后端

- `LanNetwork.java`（新增）：私网/回环/公网来源分类；`lanBind` 判定；`links(bind,port)` 枚举接入地址；设备类型识别；地址脱敏。**实际验证后追加**：首选地址优先真实网卡，VMware/Hyper-V/Docker/WSL/VPN 等虚拟网卡仅在无真实网卡时兜底（对应 V-134）。
- `LanService.java`（新增）：`info`、`devices`、`touch`、`board`、`qrPng`、启动打印接入地址。在线设备为进程内 `ConcurrentHashMap`，键为令牌 SHA-256，TTL 90 秒；看板只读聚合，不写入预约。
- `LanController.java`（新增）：四个只读接口；全部经既有 JWT 拦截。
- `WebSecurity.java`：认证成功后 `lan.touch(token, remoteAddr, userAgent, user)`；登记异常只记 debug，不影响业务请求。
- `QrImages.java`（新增）：二维码 PNG 唯一实现。`SeatCodeService.png` 改为调用 `QrImages.png(code,384)`，输出尺寸与编码参数不变；`LanService` 使用 512。
- `application.yml`：`server.address: ${STUDYROOM_SERVER_ADDRESS:127.0.0.1}`；默认行为不变。
- `SpaController.java`：增加 `/lan`，刷新前端 history 路由时返回入口页。
- `.env.example`、`application-local.example.properties`：补充局域网监听说明；实际口令/密钥仍只在 `.local`。

### 前端

- `frontend/src/api/lan.js`（新增）：四个接口封装，二维码以 `blob` 读取，避免把令牌放进图片 URL。
- `frontend/src/composables/lanBoard.js`（新增）：30 分钟粒度时间选项、默认窗口向上取整、结束时间顺延、接入/角色/活跃文案。
- `frontend/src/views/LanView.vue`（新增）：接入状态、主机地址复制、二维码、在线设备表、日期/时间看板、使用步骤；10 秒轮询设备与看板，30 秒刷新接入信息；卸载时释放二维码对象 URL。
- `frontend/src/router/index.js`：新增 `/lan`，仅 `admin` 可访问；学生/教职工直接访问会被守卫重定向到角色首页。
- `frontend/src/layouts/MainLayout.vue`：仅管理员导航增加“局域网”；学生/教职工导航不显示该入口。
- `frontend/src/components/AppIcon.vue`：新增 `lan` 图标。
- `frontend/tests/lan.test.js`（新增）：时间选项、默认窗口、顺延、文案。
- `frontend/tests/roles.test.js`：普通用户路由列表加入 `lan`，管理员用例断言可进入 `/lan`。

### 与架构方案的差异

1. 增加“真实网卡优先”过滤：架构阶段只计划排除虚拟网卡；真实启动发现 Windows 上 `NetworkInterface.isVirtual()` 未识别 VMware/Hyper-V，导致首选 URL 不可达，按 V-134 改为名称过滤 + 真实网卡优先、虚拟网卡兜底。
2. 未使用 WebSocket/SSE：按架构方案采用 10 秒轮询；未新增依赖。
3. 无数据库迁移：在线设备不持久化；看板读取既有表。因此不涉及 Flyway 版本变化。
4. 页面可见角色按用户 2026-11-26 追加指令收紧：学生/教职工端去掉“局域网”入口与页面访问，仅管理员保留。该调整只改前端路由与导航；后端 `/api/lan/*` 仍要求登录、未按角色收紧，与架构方案“待确认与决定”第 7 条一致。

## HTTPS 局域网模式（2026-11-26）

**实际改动。** `LanNetwork.links(bind,port,scheme)` 支持 http/https；`LanService` 注入 `server.ssl.enabled`，`info.server.secure`、links、`primary_url`、`qrPng` 与启动日志统一 scheme；`application.yml` 增加可选 SSL 占位；前端 `seatScanner`、`CheckinView`、`LanView` 增加 HTTPS/摄像头提示；`.env.example`、`application-local.example.properties` 增加 SSL 示例；无数据库迁移。

**验证。** `LanHttpsTest` 1/1（HTTPS URL 与二维码解码）、`LanNetworkTest` 3/3、`LanIntegrationTest` 6/6、`BatchSeatCodeIntegrationTest` 5/5；前端 `resources` 11/11、`seat-code` 20/20、`lan` 4/4；`npm run build`、`package` 通过。用本地 CA/PKCS12 启动 8443 HTTPS 实例：`/api/health` 对 `127.0.0.1` 与 `192.168.43.111` 均 200，登录 200；`/api/lan/info` 返回 `secure=true`、`primary_url=https://192.168.43.111:8443`；`/api/lan/qr.png` 真实解码为同一 https 地址；原 8090 HTTP 实例健康。真实手机安装 CA 后的摄像头授权/扫码未执行。

**差异与边界。** 默认仍为 HTTP；HTTPS 仅作为可选部署模式，不改变预约/签到规则。公共 CA 不签发私有 IP，因此使用本地 CA + 手机手动信任；不提供公网隧道、正式证书或反向代理。CA 私钥只放 `.local/`，不提交。
