## 目标、范围与验收

### 目标与可观察行为

1. 一台设备作为主机运行现有 Java/Vue 单一服务；同一局域网内的其他设备通过主机内网地址打开同一套系统，使用各自校园账号登录。
2. 所有设备共享同一份座位、预约、限制与统计事实；任一设备提交预约后，其他设备刷新即可看到同一结果。并发抢同一座位仍由现有 `booking_mutex` 与预约冲突校验串行化，只有一方成功。
3. 管理员端“局域网”页可查看：服务监听地址、当前设备接入方式、可直接打开的局域网地址与二维码、最近 90 秒在线设备、所选空间与时段的可约/已约座位聚合看板。学生与教职工端不显示该入口，直接访问 `/lan` 会被路由守卫送回角色首页；管理员保留该页。
4. 默认安全姿态不变：未显式配置时仍只监听 `127.0.0.1`；只有主机主动设置 `server.address=0.0.0.0`（或 `STUDYROOM_SERVER_ADDRESS=0.0.0.0`）并重启后，局域网设备才能访问。

### 范围边界

- 本功能的“共同预约”指**多台设备共同使用同一套预约系统与同一份预约数据**，不是“组队邀请码/多人合单”。用户 2026-11-26 已明确这一语义；不新增组队、邀请、支付、分摊等业务。
- 不新增预约写入口、不复制冲突规则、不改预约资格/期限/处罚/角色规则；预约写入仍唯一经过 `BookingService`。
- 不新增数据库表或 Flyway 迁移；在线设备是进程内瞬时状态，服务重启即清空，不用于审计或长期统计。
- 不引入 WebSocket/SSE/新依赖；页面以 10 秒轮询读取在线设备与看板，与现有统计页刷新方式一致。实时推送列为未来可选演进，不在本步预建。
- 不做公网暴露、HTTPS、反向代理、统一认证或防火墙自动配置；`0.0.0.0` 仅用于小范围教学演示，生产边界在文档中明确说明。
- 不修改 `scripts/` 启动脚本；通过 `application-local.properties` 或环境变量开启局域网监听，避免跨 D 主责范围。

## 数据、接口与流程

### 数据

- 无新增表。看板读取既有 `rooms`、`seats`、`reservations`；在线设备只存于 `LanService` 的 `ConcurrentHashMap`。
- 在线设备键为 `SHA-256(token)` 的十六进制摘要；内存项只保存摘要键、用户 id、角色、接入方式、设备类型、远端地址、首次/最近时间。接口不返回用户 id、账号、姓名或令牌。TTL 90 秒，最多 256 条，非管理员看到的他人地址脱敏到网段。
- 看板只返回空间级聚合与开放状态，不返回任何用户、预约号或时段明细。

### 接口

| 方法/路径 | 权限 | 输入 | 输出与错误 |
|---|---|---|---|
| `GET /api/lan/info` | 已登录 | 无 | `server{bind_address,port,lan_available,campus_zone}`、`client{access,remote_address,same_lan}`、`links[{name,address,url}]`、`primary_url`、`presence_ttl_seconds`、`server_now`、`hint` |
| `GET /api/lan/devices` | 已登录 | 无 | `devices[{id,role,access,device,remote_address,first_seen,last_seen,active_seconds,is_self}]`、`count`、TTL；本人完整地址，他人脱敏；管理员可看完整地址 |
| `GET /api/lan/board` | 已登录 | `date`、`start`、`end` | `date/start_time/end_time/campus_zone/server_now/campus_today`、`rooms[{room_id,name,building,floor,location,enabled,open,closed_reasons,total_seats,booked_seats,available_seats}]`、`recent_bookings_10m`、`shared_note` |
| `GET /api/lan/qr.png` | 已登录 | 无 | `image/png`，内容为首选局域网 URL；未监听局域网时 409 并说明配置方法 |

错误语义：未登录 401（既有拦截器）；缺少看板参数、日期不在 D—D+2、时长不足 30 分钟或起止倒置 400；二维码在仅回环监听时 409；其余沿用统一 `{code,message,data}` 信封。

接入方式判定：回环 → `loopback`；RFC1918/链路本地/唯一本地 IPv6 → `lan`；其余 → `other`。`same_lan` 只表示来源地址类别，不作为预约资格或权限提升依据；账号与角色仍是唯一授权来源。

### 配置与启动

```properties
# .local/application-local.properties（不提交）
server.address=0.0.0.0
```

或启动前设置 `STUDYROOM_SERVER_ADDRESS=0.0.0.0`。默认值仍为 `127.0.0.1`。启动日志会打印每个可用接入地址；页面顶部二维码与地址由 `/api/lan/info`、`/api/lan/qr.png` 提供。

### 关键流程

1. 主机启动 → `LanService.announce()` 打印接入地址；页面读取 `info` 展示监听状态与地址。
2. 其他设备打开接入地址 → 同源加载 SPA → 各自登录 → `WebSecurity` 认证成功后登记在线会话。
3. 任一设备进入“座位预约”按原流程预约；写事务仍先锁 `booking_mutex`，冲突拒绝与通知逻辑未变。
4. 设备打开“局域网”页 → 轮询 `devices`/`board`；看板只聚合，不改变预约状态。
5. 主机取消监听配置并重启 → 恢复仅回环；在线设备清空。

## 验证设计

- 纯函数单测：地址分类、监听判定、接入地址枚举、设备识别、地址脱敏。
- 真实 PostgreSQL/Redis 集成测试（仅 `studyroom_java_test`）：接入信息、仅回环时二维码 409、在线设备脱敏与不泄露令牌/账号、看板聚合与取消释放、日期边界、6 个不同账号并发抢同一座位只有 1 个成功。
- 前端单测：时间选项、默认窗口取整、结束时间顺延、展示文案；角色路由新增 `/lan` 后学生/教职工/管理员均可进入。
- 生产构建：`npm run build`。
- HTTP 联调：临时实例以 `0.0.0.0` 监听，验证健康、登录、`info`（回环与局域网两个来源）、二维码 PNG、看板、SPA `/lan`、未登录 401。
- 页面走查：同一主机用 `127.0.0.1` 登录学生 1，用 `192.168.43.111` 另一来源登录学生 2，确认接入方式为“局域网”、在线设备与看板同源。
- 不验证/不追认：第二台物理设备或手机实扫、真实 Wi-Fi 隔离、HTTPS/公网、生产并发容量；这些保持未验证。

## 待确认与决定

1. **默认监听**：保持 `127.0.0.1` 默认、局域网需显式开启。理由：不改变既有安全姿态，符合 README 原说明；用户场景可通过本地配置一键开启。是否把 `0.0.0.0` 作为教学默认值，待团队决定。
2. **是否限制只有局域网来源可预约**：本步不限制。理由：共同预约的本质是共享同一套受账号与角色保护的数据；以来源地址限制预约会削弱远程/教师演示并引入新的权限规则。该决定属技术设计，业务上是否需要“仅内网可约”待团队确认。
3. **在线设备参数**：TTL 90 秒、最多 50 条展示、10 秒刷新为教学规模候选值，非业务规则；如需审计级在线记录，应另立持久化与隐私方案。
4. **实时性**：本步轮询；如后续需要秒级同步，可在既有鉴权上增加 SSE/WebSocket，不在本步预建。

## HTTPS 局域网访问与手机摄像头（2026-11-26）

**问题与边界。** 用户实测发现：电脑本机可通过 `127.0.0.1` 请求摄像头，手机通过 `http://192.168.43.111:8090` 访问时没有权限弹窗。原因是浏览器只在安全上下文（HTTPS 或 localhost）暴露 `getUserMedia`；私有 IP 无法取得公共 CA 证书。该问题不能靠前端代码绕过，必须给手机一个受信任的 HTTPS 入口。FR-08/BR-27—31 的预约与权限规则不变。

**设计。** 提供可选 HTTPS，默认仍为 HTTP：

1. `application.yml` 增加 `STUDYROOM_SSL_ENABLED`、`STUDYROOM_SSL_KEY_STORE` 等占位；关闭时不改变现有行为。
2. [LanNetwork.java](backend/src/main/java/cn/studyroom/LanNetwork.java:55) 的 `links(bind,port,scheme)` 统一生成 `http://` 或 `https://`；[LanService.java](backend/src/main/java/cn/studyroom/LanService.java:98) 注入 `server.ssl.enabled`，`info.server.secure`、links、`primary_url`、`qrPng` 和启动日志全部使用同一 scheme。
3. 证书采用本地 CA + 服务器证书，SAN 覆盖局域网 IP（可含 `127.0.0.1`/`localhost`）；手机安装并信任 CA 后才能建立安全上下文。私钥只放 `.local/`，不提交。
4. 前端在 `isSecureContext === false` 时明确提示使用 HTTPS 或上传图片；扫码器消息同步说明手机需要 HTTPS。`/lan` 页显示访问协议，并提供 HTTPS/HTTP 下的摄像头说明。
5. HTTPS 同时保护 JWT、座位码和预约数据在局域网中的传输；不提供公网暴露、正式证书或反向代理，留作后续部署层。

**验收。** AC-36：HTTPS 开启后 `info` 返回 `secure=true`、https links/primary_url，二维码解码为 https；手机信任 CA 后在 HTTPS 页面点摄像头应出现浏览器权限提示（真实手机人工验证，不用自动测试代替）。AC-37：关闭 SSL 时原有 HTTP 地址/二维码、localhost 摄像头与预约数据不变；手机 HTTP 仍给出 HTTPS/上传提示。

**验证与状态。** `LanHttpsTest` 1/1（HTTPS URL 与二维码解码）、`LanNetworkTest` 3/3、`LanIntegrationTest` 6/6、`BatchSeatCodeIntegrationTest` 5/5；前端 `resources` 11/11、`seat-code` 20/20、`lan` 4/4；`npm run build`、`package` 通过。以本地 CA 启动 8443 HTTPS 实例：health/login 200，`info.secure=true`、`primary_url=https://192.168.43.111:8443`，二维码真实解码为该地址；HTTP 8090 回归正常。真实手机授权/扫码未执行，保留未验证。

**报告影响。** A.2 补 DEC-DEV-V030（FR-08/BR-27—31、AC-36/37，用户 2026-11-26 指令，团队待复核）；A.3 无新领域对象；A.4 无 ST；A.5 计划 SC-10（未执行）；A.6 计划 PV-10 真实手机复验（未执行）；A.7 记录 V-136（手机 HTTP 无摄像头弹窗，非安全上下文；通过可选 HTTPS + 本地 CA 修复，手机实扫待复验）；A.8/B.1/B.2/B.4 待补。报告正文与证据索引本轮未改，不宣称合规完成。
