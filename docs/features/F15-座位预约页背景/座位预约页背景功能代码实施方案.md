# 座位预约页背景功能代码实施方案

F15。范围、设计规格与验收例见同目录架构方案；本文件记录实际实现与验证结果。

## 实际改动

1. 新增素材 `frontend/public/images/booking-bg.jpg`（2099×1123，JPEG q84，369KB）：由用户消息附件参考图转换生成，未做裁剪/调色/加水印等任何加工，原图直用。
2. `frontend/src/views/BookingView.vue`：
   - 模板：根节点内第一个子元素增加背景层 `<div class="booking-bg" aria-hidden="true"></div>`。
   - 样式（scoped）：
     - `.booking-bg { position: fixed; inset: 0; z-index: 0; background: url('/images/booking-bg.jpg') center / cover no-repeat; opacity: .6; pointer-events: none; }`——铺满视口、60% 不透明度、不拦截交互。
     - `.view-heading, .booking-top, .booking-split { position: relative; }`——背景层是 z-index:0 的定位元素，按 CSS 绘制顺序（同层叠上下文中定位元素按 DOM 顺序绘制）让三个正文块进入定位层、绘制在背景层之上；不动 `.page-view` 本身（避免建立层叠上下文压住 3D 选座浮层，见架构方案约束）。
   - 业务逻辑、接口调用、3D 选座、悬浮提示均未改动。

## 实际验证

- 生产构建：`npm run build` 通过（1.82s，仅有既存的大 chunk 体积提示）。
- 前端 node 测试：`node --experimental-vm-modules --test "tests/**/*.test.js"` 共 307 条，306 过、1 失败——失败为改动前既有的 `tests/roles.test.js:115`（期望 HomeView 导出 loadRooms），与本次 diff 无关，未擅动。
- 浏览器实测（localhost:5174，学生账号已登录，1280×720 视口，DOM 计算样式核对）：
  - `.booking-bg` 存在：position=fixed，rect 1280×720 与视口一致，z-index=0，opacity=0.6，background-image=url("/images/booking-bg.jpg")；
  - 背景图请求 200、content-type image/jpeg、369,989 字节、页面内解码为 2099×1123；
  - `.view-heading`、`.booking-top`、`.booking-split` 计算样式 position 均为 relative；
  - 预约页正文（页头/条件选择/座位图）与 3D 按钮正常渲染，页面交互未被背景层拦截（背景层 pointer-events:none）。
- 其他页面：改动仅在 BookingView.vue 内，首页与其他页面无此背景（F15-5 按代码范围确认）。

## 未验证项

- 最终观感（图片画面与页面整体效果）需用户肉眼确认——本模型无图像输入能力，仅能核验 DOM 计算样式与图片加载，不能代做视觉验收。
- 若用户本意是「透明度 60% = 仅 40% 可见」，把 `.booking-bg` 的 `opacity` 从 `.6` 改为 `.4` 即可。
- 深浅主题切换未在浏览器实际切换验证（背景层为独立位图叠加，主题底色透出由 opacity 保证，属低风险）；如走查发现深色主题观感不佳，可在 `.booking-bg` 上叠加主题色遮罩调整。
