## 目标、范围与验收

目标：座位预约页（`BookingView.vue`）的页面背景使用用户提供的参考场景图，图本身以 60% 不透明度显示（页面主题底色透出 40%），静态展示、无动态效果。范围仅限预约页本身，不改变首页、其他页面、预约业务逻辑、接口与 3D 选座行为。

透明度口径：按「opacity: 0.6」实施（图占 60% 不透明度）。若用户本意是「60% 透明、仅 40% 可见」，将 `.booking-bg` 的 `opacity` 改为 `.4` 即可，属一句话原位调整。

## 当前实现与模块职责

- 现状：`BookingView.vue` 根节点为 `<div v-reveal class="page-view">`，页面无背景图，整体底色来自 `MainLayout.vue` 的 `.shell { background: var(--canvas) }`。页面正文由三个顶层块组成：`.view-heading`（页头）、`.booking-top`（条件选择条）、`.booking-split`（左条件卡 + 右座位图卡），另有 3D 选座浮层 `SeatExplorer`（`position: fixed; z-index: var(--z-dialog)`）与 Teleport 到 body 的悬浮提示（`z-index: var(--z-popover)`）。
- 改动：仅 `BookingView.vue` 增加一个背景层 `.booking-bg`（根节点第一个子元素）与少量样式；新增素材 `frontend/public/images/booking-bg.jpg`。不动 `MainLayout.vue`、公共样式与业务逻辑。
- 关键约束：不能给 `.page-view` 加 `position/z-index/isolation` 建立层叠上下文——`SeatExplorer` 渲染在 `.page-view` 内且以 `var(--z-dialog)` 覆盖全视口，若根节点建立层叠上下文会被顶栏（`--z-nav:30`）压住。

## 验证设计

- 核心成功场景：预约页加载后背景图铺满视口、opacity 0.6、正文在其上（见验收例 BG-1～BG-3）。
- 关键异常/边界场景：图片加载失败时仅无背景图、页面功能不受影响（背景层为独立装饰元素）；窄屏/滚动时背景固定不动；深浅主题均正常（BG-4～BG-5）。
- 验证方式：构建 + node 测试 + 浏览器 DOM 实测（计算样式、图片 HTTP 状态与解码尺寸）；最终观感由用户肉眼确认（本模型无图像输入能力，不宣称视觉验收通过）。

## 待确认与决定

- 事实：参考图 2099×1123，无文字（Windows OCR 无输出），为场景照片；视频帧象限均值与图片接近但不完全一致，应为对同一场景的拼接/推拉视频，用户已明确放弃动态方案，未使用。
- 假设：图片为自习室/图书馆场景实拍（依据：深木色竖条 + 蓝灰亮部 + 底部暖色反光的分区，与「自习室」语境一致）；本模型无图像输入，具体画面内容未经模型确认。若画面内容与预期不符，用户可随时更换素材文件（仅覆盖 `booking-bg.jpg`）。
- 决定：背景层用 `position: fixed + z-index: 0`，正文三个顶层块补 `position: relative` 绘制其上；透明度取 opacity 0.6。均属技术实现细节，记录于此。
- 无需求修订。
