新功能目录示例：`docs/features/F01-校园账号与权限/`，仅维护《校园账号与权限功能架构方案.md》和《校园账号与权限功能代码实施方案.md》。先架构再实施，完成结果写回原实施方案；不再创建完成报告、新版/最终版副本。小修复更新原文件或PR说明。

F04 的功能名称为「预约选座」。当前流程和 S11/S12 的历史记录见两份方案。 [功能架构方案](features/F04-预约选座/预约选座功能架构方案.md) · [代码实施方案](features/F04-预约选座/预约选座功能代码实施方案.md)

F12 的功能名称为「局域网接入与共同预约」。当前语义是同一局域网内多台设备登录同一服务并共用预约数据，不是邀请码组队；页面与导航仅管理员可见，学生/教职工端不显示入口。可选 HTTPS 模式用本地 CA 让手机获得摄像头所需的安全上下文；默认仍为 HTTP。规则与验证见两份方案。 [功能架构方案](features/F12-局域网共同预约/局域网共同预约功能架构方案.md) · [代码实施方案](features/F12-局域网共同预约/局域网共同预约功能代码实施方案.md)

F13 的功能名称为「批量生成座位二维码」。管理员一次为所有缺少座位码的座位补齐当前码，已有码座位跳过且不改写；与单座位首次生成同格式，可重复执行且幂等。规则与验证见两份方案。 [功能架构方案](features/F13-批量生成座位二维码/批量生成座位二维码功能架构方案.md) · [代码实施方案](features/F13-批量生成座位二维码/批量生成座位二维码功能代码实施方案.md)

`docs/design/视觉改版-*` 是界面视觉改版记录（首页 hero、用户端首页、座位预约页背景等），按用户设计稿实施，属于纯展示改动，不对应 FR/BR/AC，不占需求功能编号，也不放进 `docs/features/` 的功能目录（该目录只放 Fxx 需求功能方案）；各文档的验收例使用本地编号（如 BG-1）。

本仓库已有基线、迁移和验证说明予以保留，不为追求目录形式批量重命名。新类别先在本索引登记，不造空报告或大量 .gitkeep。业务需求按用户提供的最新报告确认后导入，不把外部参考资料或第三方示例的问答范围当成本项目要求。

正式需求及课程报告是独立交付，不能被两份功能方案替代。图模型源与导出保持编号对应；报告以必要段落引用证据，不复制完整聊天、测试日志或真实学生隐私。未执行的验证写未验证，人工取舍只记录真实发生的内容。
